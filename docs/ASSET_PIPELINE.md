# Asset Pipeline

This document defines how pixel-art sprites are organized. Sprites are generated by agents (see ADR-013) and can be replaced by hand-crafted artwork at any time without code changes.

---

## Directory Structure

```
Assets/
└── Pets/
    ├── Cat/
    │   ├── manifest.json
    │   ├── idle/
    │   │   ├── frame_00.png
    │   │   ├── frame_01.png
    │   │   └── frame_02.png
    │   ├── walk/
    │   │   ├── frame_00.png
    │   │   ├── frame_01.png
    │   │   ├── frame_02.png
    │   │   └── frame_03.png
    │   ├── sleep/
    │   │   └── frame_00.png
    │   └── run/
    │       ├── frame_00.png
    │       ├── frame_01.png
    │       ├── frame_02.png
    │       └── frame_03.png
    ├── Dog/
    │   ├── manifest.json
    │   └── ...
    ├── Parrot/
    ├── Rabbit/
    ├── Turtle/
    ├── Dinosaur/
    └── Hamster/
```

Each pet has its own folder under `Assets/Pets/`. Each animation state has a subfolder containing numbered frames.

---

## Manifest Format

Each pet folder contains a `manifest.json` that describes the pet and its animations:

```json
{
  "name": "Cat",
  "version": 1,
  "spriteSize": {
    "width": 32,
    "height": 32
  },
  "scale": 2,
  "anchorY": 0,
  "animations": {
    "idle": {
      "fps": 4,
      "loop": true
    },
    "walk": {
      "fps": 6,
      "loop": true
    },
    "run": {
      "fps": 8,
      "loop": true
    },
    "sleep": {
      "fps": 2,
      "loop": true
    },
    "jump": {
      "fps": 8,
      "loop": false
    },
    "interaction": {
      "fps": 6,
      "loop": false
    }
  },
  "movement": {
    "walkSpeed": 30.0,
    "runSpeed": 60.0
  }
}
```

### Manifest Fields

| Field | Type | Required | Description |
|-------|------|----------|-------------|
| `name` | String | Yes | Display name of the pet |
| `version` | Int | Yes | Manifest format version (currently 1) |
| `spriteSize` | Object | Yes | Native pixel dimensions of each frame |
| `spriteSize.width` | Int | Yes | Frame width in pixels |
| `spriteSize.height` | Int | Yes | Frame height in pixels |
| `scale` | Int | Yes | Integer display scale (e.g., 2 = each sprite pixel becomes 2×2 points) |
| `anchorY` | Int | No | Vertical offset in pixels from the sprite bottom to the "feet" position. Default: 0 (feet at bottom edge) |
| `animations` | Object | Yes | Map of animation state name → animation config |
| `animations.{state}.fps` | Number | Yes | Frames per second for this animation |
| `animations.{state}.loop` | Bool | Yes | Whether the animation loops or plays once |
| `movement.walkSpeed` | Number | No | Walk speed in points/second. Default: 30.0 |
| `movement.runSpeed` | Number | No | Run speed in points/second. Default: 60.0 |

## File Naming Convention

### Frame Files

- Format: `frame_XX.png` where XX is a zero-padded two-digit number
- Numbering starts at `00`
- Frames play in numerical order: `frame_00.png` → `frame_01.png` → `frame_02.png`
- Maximum 99 frames per animation

### Examples

```
frame_00.png  ← first frame
frame_01.png  ← second frame
frame_02.png  ← third frame
```

### Allowed Image Formats

| Format | Extension | Recommended |
|--------|-----------|-------------|
| PNG | `.png` | **Yes** — lossless, supports transparency |

PNG is the only supported format. Do not use JPEG, GIF, WebP, or other formats. PNG provides lossless quality and alpha transparency, which pixel art requires.

---

## Sprite Dimensions

- All frames within a single pet MUST have the same pixel dimensions
- Dimensions are declared in `manifest.json` under `spriteSize`
- Common sizes: 16×16, 32×32, 48×48, 64×64 pixels
- Non-square sprites are allowed (e.g., 32×48 for taller pets)

---

## Scaling Rules

- Sprites are rendered at integer scale only. The `scale` field in the manifest defines the multiplier.
- Example: a 32×32 sprite at scale 2 renders as 64×64 points
- Rendering uses **nearest-neighbor interpolation** — no bilinear filtering, no blur
- On Retina (2× backing), a 32×32 sprite at scale 2 = 64×64pt = 128×128 physical pixels

### Scale Selection Guidance

| Sprite Size | Scale | Display Size (points) | Recommended For |
|-------------|-------|-----------------------|-----------------|
| 16×16 | 4 | 64×64 | Tiny pets |
| 32×32 | 2 | 64×64 | Standard |
| 32×32 | 3 | 96×96 | Larger display |
| 48×48 | 2 | 96×96 | Detailed pets |

---

## Anchor Point

The `anchorY` field defines where the pet's "feet" are relative to the bottom of the sprite, in pixel units.

- `anchorY: 0` — feet are at the very bottom row of the sprite (default)
- `anchorY: 2` — feet are 2 pixels above the bottom (e.g., for pets with a shadow or ground detail in the sprite)

The pet engine subtracts `anchorY × userScale` from the bottom-Dock window origin so the visible feet align with the measured Dock top plus the normal 4pt margin. This is recalculated when the Dock or pet size changes. Existing manifests with `anchorY: 0` retain their placement.

---

## Direction / Facing

- Sprites are drawn facing **right** by default
- The engine flips sprites horizontally when the pet moves left
- Do NOT provide separate left-facing sprites (unless the sprite is asymmetric and flipping looks wrong, in which case a future `"asymmetric": true` manifest flag may be added — TODO)

---

## Fallback Behavior

When an animation state is missing:

| Missing State | Fallback |
|---------------|----------|
| `walk` | Use `idle` |
| `run` | Use `walk`, then `idle` |
| `sleep` | Use `idle` |
| `jump` | Use `idle` |
| `interaction` | Use `idle` |
| `idle` | **Error** — `idle` is required |

A pet folder MUST contain at minimum:
- `manifest.json`
- `idle/` folder with at least one frame

All other animation states are optional.

## Adding a New Pet

### Signature sequence timing

`special/` frames play once, in filename order, across the fixed five-second skill phase. The coordinator derives FPS from frame count / 5; `special.loop` is false in generated manifests. Ending a sequence early does not shorten the phase.

An optional `movingFrames` integer in an animation configuration specifies how many leading special frames translate along the Dock at walking speed. Existing manifests without it remain stationary during skills. Messi uses 8 moving frames, followed by stationary goal celebration and World Cup frames. Walking speed is at least the available screen-edge span / 10 seconds, so large displays remain traversable regardless of the base activity setting.

`scripts/slice_sprites.py` extracts existing artist-authored cells, reflects the cat's side-facing walk, and uses nearest-neighbor scaling. Do not regenerate `Assets/NewPetDesign/`. Yarn and sleep marks are runtime pixel overlays, not modifications to those source sheets.

To add a new pet type (e.g., "Fox"):

1. Create folder: `Assets/Pets/Fox/`
2. Create `manifest.json` with pet configuration
3. Create `idle/` folder with at least `frame_00.png`
4. Optionally add `walk/`, `run/`, `sleep/`, `jump/`, `interaction/` folders with frames
5. No code changes required — the asset loader discovers pets by scanning `Assets/Pets/`

## Validation Checklist for Artists

- [ ] All frames are PNG with transparency
- [ ] All frames have the same pixel dimensions
- [ ] Frame dimensions match `spriteSize` in manifest
- [ ] Frames are named `frame_00.png`, `frame_01.png`, etc.
- [ ] `idle` animation has at least one frame
- [ ] `manifest.json` is valid JSON
- [ ] Sprite is drawn facing right
- [ ] No anti-aliasing on sprite edges (pixel art should have hard edges)
- [ ] Transparent background (no solid background color)

## Baby Yoda component artwork

Run `python3 scripts/generate_baby_yoda.py` to regenerate only `Assets/Pets/BabyYoda/`. The existing Pillow dependency is reused; other pet assets and source sheets are untouched. One canonical green head with pure black eyes, ears, gray torso, sleeves and feet is reused for every pose. Animation only translates those parts and adds eyelids, a gray hood, or a green saber. Output is 64×64 RGBA with 2× nearest-neighbor blocks and binary alpha.

The twenty-frame signature uses 8 hood frames, 4 draw/ignition frames and 8 training frames at 4fps. A separate `training/` loop is available to the loader, while the normal 25s behavior cycle plays training as the end of `special/`. `anchorY: 2` records the two transparent pixels beneath the feet.

Verify model invariants and saved frames with `python3 -m unittest discover -s Tests/AssetTests -v`.
